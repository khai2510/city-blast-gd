# PERF-1124: "TestFlight build 9 giật, không mượt" (Agents-Game, 24/11)

Base: `868b2e5`. Only safe wins are shipped: the picture, the gameplay and the physics result of the same taps are unchanged.
Mac files (hard-level data, `g7…` blocks of `pipeline7/engine.js`, `release/`) are not touched. No TestFlight build.

New build steps (last in `src/tools/build-main.js`): `perf2` (`src/main/perf2.js`, the fixes, `?perf2=0` = off) and
`fps` (`src/main/fps.js`, the hidden meter + probe). Tools in this folder: `prof.js` (per-frame cost in planning / turn /
collapse / rest), `physprof.js` (physics in step space + determinism fingerprint), `shots.js` (option shots).

**How to read the numbers.** Headless Chrome + SwiftShader on a shared 4-core VM, 393 × 852 CSS px at DPR 3 (an iPhone 15).
SwiftShader rasterises on the CPU: with the 3D canvas hidden the same page runs at 60 fps, with it shown at 3–6 fps, so every
headless frame time is ~95 % GPU fill. Use the fps columns as ratios between builds / flags only, never as phone numbers.
JS, physics ms and draw-call / triangle counts are real (the VM is roughly a 2018 phone for wasm).

## 2. Causes, ranked

1. **GPU fill, every frame**: 1.34 Mpx × 4× MSAA with PCF shadow sampling and fog, redrawn at 60 Hz even when nothing
   moves. The 3× → 2× cap (14/11, P2) is already in and halves it. What is left is the look itself (options below), plus
   frames that did not need drawing: the settled result card redrew the scene and **the shadow map every frame** (debris
   whose `sleeping` flag goes stale once physics stops were re-uploaded with the same matrix and flagged "moved").
2. **The collapse: Rapier solver 12 iterations × 4 PGS** on 150–430 awake bodies + 60 debris: 5–10 ms a step on the VM
   (worst single step 32 ms on Sky Saucer), up to 2 steps a frame. With a 9 ms budget the frames alternate 1 step / 2 steps
   (16 / 33 ms), which reads as judder. The solver settings decide which pieces fall, so they stay.
3. **One-off hitches at the two big moments**: the first BLAST of a session uploaded the 1024 × 1024 particle atlas inside the
   blast frame (texImage2D 21.5 ms on the VM, plus the image decode on iOS), and the first TNT placed compiled the charge
   sprite program under the finger (the engine's warm-up runs before the occlude / look patches re-key that material).
   Blast frame JS: 50–54 ms.
4. JS around the solver: wasm vector round trips (above), the monument camera clearance / pip code (100–400 KB a frame), the
   idle prebuild of the next level while planning a hero (≤ 3 ms budget, at least one step: up to 5–7 ms on a frame) and on the
   result card (7–9 ms a frame while it runs). Not the main cost; left as is (the prebuild is by design, P1 of 14/11).

Not a cause: draw calls (20–46, everything is instanced), triangles (≤ 72 k incl. shadow), DOM (no running CSS animation in
steady play; the booster "Unlocked" card animates while it is up), the pixel ratio governor (2 = 2 on a 3× phone, no flip).

## 3. What changed (`src/main/perf2.js`, each part has its own off flag)

| | Change | Proof (before → after, same build with `?perf2=0`) |
|---|---|---|
| S1 | **Identical frames are not redrawn.** Before each render a signature of everything the GPU draws (canvas size, camera pose + projection incl. shake / view offset, fog, lights, every visible object's matrix, geometry / attribute / instance versions, material version, colours, opacity, maps and every uniform value incl. the onBeforeCompile ones) is compared with the last drawn frame. Same → the canvas keeps its picture. Plain values must match exactly as float32, matrices within 2e-5 (< 0.01 px at the closest zoom). Never with a pending shadow update or the FXAA path; at least one draw a second. `?perfskip=0` | settled result card, slot 52: 0 → **299 of 305 frames skipped**, headless 5.9 → 50.7 fps, JS 1.28 → 0.47 ms · slot 12: 0 → 294 / 300, 5.5 → 50.0 fps. Planning, turn and collapse: 0 skipped (the camera always moves), so no change there. |
| S4 | **Unchanged poses are not re-uploaded.** A member / debris piece is rewritten only when the step count, the interpolation alpha or its pose changed since its last write (bent members always). Stops the per-frame instance upload + shadow-map redraw on a settled lot; S1 needs it to see the result card as still. `?perfpose=0` | result card: shadow map redrawn every frame → not at all; same matrices. |
| S2 | **Warm-up after every patch.** `warmUp()` runs once more after all patches, and the particle atlas + the charge sprite images are uploaded (`renderer.initTexture`) as soon as they decode. Same programs and textures, only earlier. `?perfwarm=0` | first TNT: 1 program compiled on the tap → 0 · first BLAST: 1024² atlas texImage2D 21.5 ms in the blast frame → none · worst collapse frame JS 53.7 / 50.0 / 50.1 ms → **23.5 / 27.0 / 31.7 ms** (12 / 52 / 53) |
| S3 | **No 2nd fixed step a frame cannot afford.** The 2nd step of a frame also needs (physics so far × 2 + last frame's other work) < 14 ms. Every step is still exactly DT; an overloaded phone drops the time it cannot simulate one frame at a time, instead of alternating 16 / 33 ms frames. No effect on a phone that keeps 60 fps. `?perfstep=0` | collapse steps a frame 1.81 / 1.86 / 1.15 → 1.75 / 1.41 / 0.95, physics ms a frame 8.3 / 11.8 / 13.0 → 8.3 / 9.8 / 10.8 (VM) |

Determinism (same taps, same pieces fall):
- `physprof.js` scripted collapse on 12 / 52 / 53: levels6 log hash, step and % identical before / after
  (`dc33769f@180 0.005 %`, `b5324c18@550 93.343 %`, `e19a1652@720 16.577 %`).
- R-11 `determinism-check.js` all of L1–12, 2 repeats × seq / after / fresh / wait / raf + 1 live run: every mode identical

  reference `done@587 96.7 %`, 3 / 3 live runs on both builds): a pre-existing live-vs-manual gap on slot 7, not from this pass
  (the slot 7 intro card, FIX-1124 UX-89, is the likely cause; worth its own look).

## 4. Options that change the look (not shipped, Khai decides)

Shots: `opt-*-L53-before-after.jpg` (this folder) (left = now, right = option; Sky Saucer planning, 3× phone).

| Option | Gain (measured) | What you see |
|---|---|---|
| A. Pixel ratio 1.5 on 3× phones (`?pr=1.5`) | planning +35 % headless (1.34 → 0.75 Mpx) | slightly softer edges and textures (`opt-pr15`) |
| B. Shadows off on weak phones | planning +20 % (collapse also loses the shadow pass: 10–20 calls, 10–22 k tris every 2nd frame) | no building / debris shadows (`opt-noshadow`) |
| C. FXAA instead of 4× MSAA | +22 % | softer, slightly blurred thin lines (`opt-noaa`) |
| D. 512 shadow map | ±0 % headless (not worth it) | blurrier shadow edges (`opt-shadow512`) |
| E. Solver 6 iterations × 2 PGS (`?it=6&pgs=2`) | ms / step mean −47 / −46 / −10 %, peak −31 / −32 / −46 % (12 / 52 / 53) | **changes results**: 52 93.3 → 99.9 %, 53 16.6 → 89.5 % with the same TNT: every level would need re-gating |
| F. Debris put to sleep sooner / debris cap 60 → 30 | not measured (changes which pieces fall) | fewer flying pieces; re-gating needed |

Recommended first if the meter shows the phone GPU-bound in planning: A (biggest gain, least visible). E / F only with a level re-gate.

## 5. The fps meter on the phone (dev only, nobody sees it by default)

- **5 quick taps on the "Level N" pill** at the top of a level (within 3 s) → a small line at the top centre:
  `58 fps  worst 34 ms  R 2.1  P 4.3` = frames in the last second, the longest frame in that second, ms a frame of render
  (CPU submit) and of physics. Green ≥ 55 fps, yellow ≥ 40, red below. 5 more taps hide it. It stays on across restarts on
  that phone (localStorage) until hidden again.
- Or open the game with `?fps=1` (`?fps=2` also waits for the GPU after each render, so R includes GPU time: measuring only).
- How to read it: low fps with small R and P = the GPU (options A–D help); big P in the collapse = physics (option E / F);
  a single big "worst" at BLAST = a hitch.
- Shot: `fps-meter-L12.jpg`.
